5.1 Pre-Commit Hook (.githooks/pre-commit)

#!/bin/sh
# Rejects commit if any staged file contains whole word TODO or FIXME
echo "🔍 Running pre-commit hook: Checking for TODO or FIXME in staged files..."
STAGED_FILES=$(git diff --cached --name-only --diff-filter=ACM | grep -v "^\.githooks/")
if [ -z "$STAGED_FILES" ]; then exit 0; fi

FOUND_FLAGS=0
for FILE in $STAGED_FILES; do
  if git show ":$FILE" | grep -E -n "\b(TODO|FIXME)\b" > /dev/null 2>&1; then
    echo "❌ Error: Commit rejected! Staged file '$FILE' contains forbidden markers (TODO or FIXME):"
    git show ":$FILE" | grep -E -n --color=always "\b(TODO|FIXME)\b"
    FOUND_FLAGS=1
  fi
done
if [ $FOUND_FLAGS -ne 0 ]; then
  echo "🚫 Aborting commit. Please resolve or remove all TODO / FIXME comments before committing."
  exit 1
fi
echo "✅ Pre-commit check passed: No TODO or FIXME found."
exit 0

5.2 Commit-Msg Hook (.githooks/commit-msg)

#!/bin/sh
# Validates commit message length (>= 10 chars) and prefix (feat:, fix:, docs:, refactor:, chore:)
COMMIT_MSG=$(cat "$1" | head -n 1)
echo "🔍 Running commit-msg hook: Validating commit message format..."

MSG_LEN=${#COMMIT_MSG}
if [ "$MSG_LEN" -lt 10 ]; then
  echo "❌ Error: Commit message is too short ($MSG_LEN characters). Minimum required is 10 characters."
  exit 1
fi

VALID_PREFIX_REGEX="^(feat:|fix:|docs:|refactor:|chore:)[[:space:]].+"
if ! echo "$COMMIT_MSG" | grep -E "$VALID_PREFIX_REGEX" > /dev/null 2>&1; then
  echo "❌ Error: Commit message must start with: feat:, fix:, docs:, refactor:, or chore:"
  exit 1
fi
echo "✅ Commit-msg check passed: Conventional prefix and length verified."
exit 0

5.3 Written Analysis (Why Hooks Aren't Shared & Bypass Risks)

1. Why hooks in .git/hooks are not shared by git push:
The .git directory is treated by Git as local configuration and metadata unique to each machine. Git purposefully refuses to transfer .git/hooks across network remotes as a fundamental security measure; if hooks were pushed and executed automatically on clone, malicious repositories could execute arbitrary shell scripts on developers' machines without their knowledge.

2. How a team can share them:
A team can store hook scripts in a tracked directory within the repository (such as .githooks/). Each developer then runs the command: git config core.hooksPath .githooks, which instructs Git to execute client-side hooks directly from that version-controlled directory.

3. The risk of git commit --no-verify:
The --no-verify flag bypasses client-side pre-commit and commit-msg hooks entirely. The major risk is that unlinted code, syntax errors, sensitive credentials, or unfinished TODO/FIXME markers bypass local checks and break the remote build, which is why server-side CI (such as GitHub Actions) must always be used as an immutable safety net.
